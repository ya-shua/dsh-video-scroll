# snow-video-kit 设计文档

> 版本：v0.3.0 · 写于 2026-11-03 · 由 ZCode 会话设计并实现
> 定位一句话：**依附 SnowLuma 运行的 QQ 智能体刷视频工具包**——QQ 连接成功即就绪，
> 她自己能调用 `video_*` 工具，值班轮的大脑用自填 key（OpenAI 兼容），彻底脱离 DSH，
> 带跨平台记忆库（抖音、B站互通）、花费面板和全新设计的工作台。
> 使用说明看 `README.md`；全部改动时间线看 `插件/变动记录.md`。

---

## 一、生态位置

```
QQ ── SnowLuma(OneBot v11, 3000/3001) ──┬── 旧 qq-bridge(3100) → DSH agent   ← 现在的聊天链路
                                        └── snow-video-kit(8412)             ← 本软件（工具面 + 值班轮）
环形的心(ringmind, 5173) ── 记忆库（记忆库.db，九环设计）── mcp/server.mjs(ring_* 工具)
dsh-video-scroll(8390, DSH 内) ── B站/抖音原装全功能面板 + 原装引擎（与本软件并存）
```

- 本软件**不依赖 DSH 进程**：B站机器是 `~/.dsh/bili-duty` 里的独立 Python MCP，抖音机器是
  `douyin-duty` 里的 Chrome/签名器/venv——它们本来就不在 DSH 里跑，只是家目录名字叫这个。
- 大脑**不依赖 DSH**：值班轮的判断/写日报由 OpenAI 兼容 API（自填 key）完成。
- 与 DSH 的关系只剩历史包袱：家目录路径、可复用的 venv/cookie/章程。

## 二、组件

| 组件 | 文件 | 职责 |

## 三、关键设计决策（踩坑换来的）

### D1 单入口 entry（v1.0.0 → v1.1.0 的教训）
DSH 的浏览器 client-modules 扫描（`exactPackageSpecifier`）**不接受带 `/` 的条目名**。
v1.0.0 曾用 `dsh-video-scroll/bili` 子路径 entry：宿主半端正常挂载，但两条 entry 被静默
排除出浏览器 bundle 图 ⇒ **设置页面板消失**。结论：任何 DSH bundle 的条目名只能用裸包名；
多功能的拆分放在 `apply()` 里用 `ctx.plugin` 挂子 fiber 完成（本包即此模式）。

### D2 大脑替换的边界（哪些能脱离 DSH，哪些不能）
- **能**：值班轮的判断/写日报（LLM 会话）、配置读写（家目录文件）、面板（自己的 HTTP 服务）。
- **机器本来就在 DSH 外**：B站 Python MCP、抖音 Chrome/签名器——直接复用家目录资产。
- **换掉 DSH headless 需要补的四件事**：工具调用循环（MCP↔tool_calls 胶水）、章程注入
  （duty.md + 动态段）、判重/额度（宿主文件操作）、日报落盘（固定格式解析）。
- DSH 特有的「attachments/视觉」未复制：kit 大脑当前纯文本（见第九节）。

### D3 QQ 门控
值班轮放行前强制 `requireOnline()`（守望器 30s 探测）。理由：值班轮的产品语义是
「QQ 语境下的自动刷」，离线时跑了也没有投递/告知通道。工作台/她的状态卡如实显示离线。

### D4 记忆库 = 独立 SQLite + 可接入路径
- 引擎选 `node:sqlite`（内置零依赖，与环形的心同款），WAL。
- 默认 `data/video-memory.db`；`config.json → memory.dbPath` 可指向任意 SQLite 文件——
  「可接入数据库的接口」指的就是这一层：接口不变，库可换。
- 表：`videos`（挑过的视频，UNIQUE(platform,vid) 幂等入库）、`interactions`（评论/私信）、
  `events`（事件流）、`token_usage`（花费记账）。
- **互通机制**：两边值班轮自动 `ingestReport` 入库；轮前把「最近 N 天**两平台**已推内容」
  注入提示词（避免重复选题与话术）；她的 `video_memory` 工具与工作台「记忆库」页共用同一组查询。
- 与环形的心（记忆库.db）的关系：**不直接写她的库**（九环设计是她的认知边界），
  互通走第七节的适配器与 `ring_ingest`（待办）。

### D5 值班轮的双形态
- 抖音 = **采集(纯代码) + 单次判断**：证据由 forward-pick.py 采好，模型纯判断，
  日报要求 `### <视频ID>` 标题行，宿主解析落盘并数配额——一次调用，便宜可控。
- B站 = **多轮工具循环**：模型自主 荐→读字幕/评论→`duty_report_append` 窄口落盘，
  配额在驱动层强制；转写（ASR）属 B站侧能力，v0.3 未接。
- 面板里的「现在跑一轮」被代理层**统一拦截改走本软件引擎**（key 大脑），保证大脑不分裂。

### D6 双面板策略（8390 与 8412）
- 8390（dsh-video-scroll 内，随 DSH）：两个原装 React 面板**原样复用**（iframe 内嵌进
  8412 的「综合面板」页签），扫码/评论/私信等全功能——API 由 8412 代理给 DSH 插件进程，
  例外 `*/run` 拦截改走本软件（见 D5）。
- 8412：本软件工作台（总览/大脑/记忆库/花费/工具/日志）。
- 一个网址装下全部；DSH 关闭时 8390 面板功能降级（提示需 DSH），值班轮与状态不受影响。

### D7 环形的心适配 = 聚合代理，不改它
环形的心没有插件系统，它的接口是 `mcp/server.mjs`（ring_* 工具）。适配器
`ring-adapter.mjs` 把它作为子 MCP 代理、与 video_* 聚合成一个入口：
- 环形的心侧**零改动**（它更新工具自动跟上）；
- ring_* 不可用时降级（video_* 不受影响，错误明确）；
- 路径可配（`config.json → ring.mcpServer`），默认 `桌面\插件\环形的心\mcp\server.mjs`。

### D8 软件化边界
`install.bat` = 自检 + 桌面快捷方式 + 开机自启（Startup 文件夹放无窗口 VBS）+ 立即启动。
不做单文件 EXE（SEA 需重造路径解析且要联网 postject），「绿色软件 + 自启」已满足使用。

## 四、值班轮时序（以抖音为例）

```
触发（手动/窗口计划/她的 video_run_round）
  → rounds.runRound：并发闸 → QQ 门控 → state/round-douyin.json = running
  → forward-pick.py（curl_cffi+签名器）→ round-evidence.json（list[12]）
  → 大脑单次调用：system=duty.md+persona+动态参数+记忆块 / user=证据JSON
  → 返回日报（### <视频ID> 标题行）
  → 落盘 out/<日期>.md（追加）+ seen.md（判重）+ videomem.ingestReport（跨平台记忆）
  → 记账 token_usage（kind=douyin-round）
  → state = done（含 summary）
```

B站轮差异：spawn `mcp_server.py`（stdio MCP）→ `chatWithTools` 多轮（白名单工具）→
模型自主调用 `duty_report_append` 等窄口工具落盘 → 收尾总结。

## 五、接口清单

| 接口 | 形式 | 鉴权 | 用途 |
|---|---|---|---|
| stdio MCP | `node src/kit-mcp.mjs` | 无（子进程） | 挂进 DSH（她现在的大脑）/ 任何 MCP 客户端 |
| HTTP MCP | `POST 127.0.0.1:8412/mcp` | 工作台令牌（?token= / x-console-token） | QQ 智能体/第三方远程接入（无状态 JSON-RPC） |
| 工作台 API | `GET/POST 127.0.0.1:8412/api/*` | 会话 cookie（?token= 登录） | 总览/大脑/记忆库/花费/日志/跑轮 |
| 内嵌面板 | `GET /panel.html` + `/app.js` + `/vendor/*` | 同上 | 原装面板（API 代理 8390，`*/run` 例外） |

`video_*` 工具：`video_status` / `video_latest_report` / `video_run_round`（异步派发）/
`video_bili_hot` / `video_bili_search` / `video_memory`（跨平台记忆查询）。

## 六、花费记账

- 每次 `chat` / `chatWithTools` 收尾按 OpenAI `usage` 记账：`token_usage(at, kind, model,
  prompt_tokens, completion_tokens, total_tokens, cost)`，kind 区分 bili-round /
  douyin-round / test。
- 成本 = 价格表折算（¥/1M tokens，按模型可配 + 默认兜底），**仅估算**，页面上明示。
- 工作台「花费」页：今日/本月/累计、按任务分类、14 天趋势、最近 50 笔、价格表编辑。

## 七、配置与状态

| 文件 | 内容 | 备注 |
|---|---|---|
| `config.json` | snow/brain/bili/douyin/schedule/memory/web 全部配置 | 首次启动自动落盘；无热重载（改后重启） |
| `state/brain-key` | 大脑 key | 不回显、不进配置 |
| `state/console-token` | 工作台登录令牌 | 桌面快捷方式自动携带 |
| `state/round-*.json` | 值班轮进度/结果 | 并发闸依据（2h TTL） |
| `state/kit.log`、`web.log` | 运行日志 | |
| `~/.dsh/{bili-duty,douyin-duty}` | 两个子机器的家目录（venv/MCP/cookie/章程/out/seen） | **复用，不迁移** |

## 八、安全边界

- 一切只听 `127.0.0.1`；工作台令牌 + 会话 cookie；MCP/代理路由同令牌。
- 代理只放行两个子插件前缀（`/api/bili-duty|douyin-duty`），`*/run` 走本软件引擎。
- 默认**不自动发评论/私信**（douyin autoSend=false，B站白名单无发送类工具）。
- key/令牌不回显、不进导出；报告里的对外文本经插件的敏感词闸（sender SENSITIVE_RE 同源）。

## 九、已知边界与限制

1. 视觉：B站有封面/抽帧工具，但 kit 大脑当前**纯文本**——多模态 key 需要补图片传递（未实现）。
2. ASR：B站侧有完整方案（faster-whisper，`.venv-asr` 未装），kit 未接。
3. QQ 门控依赖 SnowLuma 在线；SnowLuma 的 QQ 登录属于它的界面操作。
4. 值班轮的「发评论/私信」（autoSend）默认关；开了也只写日报 v0.3。
5. 综合面板的完整功能需要 DSH 在跑（8390 代理依赖）。
6. 8390 面板样式依赖 DSH 设计变量（`--dsw-alias-*`）——内嵌/独立页已自带一套深色变量。

## 十、排障速查

| 症状 | 看哪里 |
|---|---|
| 工作台打不开 | `state/web.log`；端口 8390-8398 无关，工作台是 8412 起 |
| 值班轮总是「未连接」 | SnowLuma 是否在线（总览 QQ 卡）；`onebot_*.json` 端点是否可达 |
| 面板空白/无样式 | 设置 → 插件 → 插件列表 看同步失败；确认 DSH 重启过 |
| B站轮报「未登录」 | 综合面板 → 刷B站 → 扫码（`bili_credential.json` 缺失） |
| 大脑报「未配置」 | 工作台 → 大脑 → 填 key → 测试连通 |
| 启动失败 | `state/kit.log`、`state/web.log`；8412-8420 全占时会放弃本轮 |

## 十二、版本控制

本目录是 git 仓库（main 分支，2026-11-03 初始化）：

- `v0.3.0` 标签 = 首个入库版本（工作台/记忆库/花费/环形的心适配器齐备）；
- 运行期数据**不进版本**：`state/`（key/令牌）、`data/`（记忆库文件）、`*.log`；
- 推送到 GitHub：先在 GitHub 建空仓库，再 `git remote add origin <url> && git push -u origin main --tags`
  （本机 gh CLI 未登录，需先 `gh auth login` 或改用 https 凭证）。
