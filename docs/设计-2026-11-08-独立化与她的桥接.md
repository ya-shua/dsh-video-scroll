# 设计：刷视频插件独立化 + 桥接海螺（2026-11-08）

> 一句话：让 `snow-video-kit` 不带 DSH 也能跑，并且跑的时候知道**她是谁、记得什么、该怎么说话**；
> 需要时还能**看画面、听声音**（借留影的模型），两档可切。

---

## 一、为什么改

改之前是两套并存、互相打架：

| 线 | 状态 |
|---|---|
| `snow-video-kit`（8412） | 自己带 key 跑大脑，**能用**；但值班轮不知道她的人设/记忆，日报读起来像分析报告 |
| `douyin-duty` 的 DSH headless 轮 | 还在按夜窗拉起 `DeepSeek Harness.exe --profile headless`，**每轮必挂**（headless profile 的 `mcp-ring` 路径少了 `插件\` 一级） |
| DSH 的 `mcp-ring` / `mcp-lumisphere` | 只让 DSH 会话里有工具，跟 kit 无关，纯属重复接线 |
| 看画面 | B站 `bili_frames` 能抽帧，但 `mcpclient` 把图片内容**扔了**，文本大脑根本看不到 |

目标：

1. kit **完全独立**：只依赖 SnowLuma 的 node、两个家目录、海螺的 HTTP（可选）
2. 值班轮 = **她**在刷：人格、记忆、口吻都来自海螺那边
3. 日报保留程序要的 `### ID` + 档位行，正文换成她的话
4. 看/听复用**留影**（它的视觉与 ASR 已配好），`fast` / `deep` 两档可切
5. 剪掉 DSH 的四根线，DSH 不开也能用

## 二、架构

```
snow-video-kit（8412，自己的 key，独立进程）
│
├─ conch-bridge.mjs ── 读「她」
│    ├─ GET http://127.0.0.1:7801/api/roles/{persona}   当前人格（30 分钟缓存）
│    ├─ GET http://127.0.0.1:7801/api/messages          她说过的原话 → 语气样本
│    └─ stdio 环形的心 mcp/server.mjs                   ring_recall / ring_overview → 记忆片段
│
├─ eyes.mjs ── 「看 + 听」（import 留影的模块，不走 HTTP、不写它的记忆库）
│    ├─ describeImage()      故事板帧 / 单帧 → 文字
│    ├─ describeVideo()      抖音直链 → 抽帧 + ASR 一步到位
│    └─ transcribeAudio()    只转写音轨（B站没字幕时）
│
└─ bili.mjs / douyin.mjs ── prompt 注入
     system = 章程 + 人设摘要 + 记忆片段 + 语气样本 + 本轮参数 + 「用她的话写」
```

### 各平台怎么取素材

| | 画面 | 声音 |
|---|---|---|
| **B站** | `bili_frames` 拿故事板帧（免费、不下整条视频）→ 留影 `describeImage` 逐帧 | 有字幕读 `bili_subtitle`；没字幕才 `yt-dlp -f bestaudio` 只拉音轨 → 留影 `transcribeAudio`；两条都失败才如实写「没听到」 |
| **抖音** | `tools/dy-play-url.mjs`：签名器打 `/aweme/v1/web/aweme/detail/` → `video.play_addr.url_list` → 下载 → 留影 `describeVideo`（抽帧 + ASR 一步到位） | 同左 |

### 抖音直链为什么这么绕（实测记录）

- `iesdouyin.com/share/video/<id>`：HTTP 200，但 72 KB 空壳，**没有 `play_addr`**
- `douyin.com/video/<id>`：无头浏览器打开会**跳 `/chat`**，`<video>` 的 src 是空
- ✅ 只有**签名详情接口**给直链：`dy-signer.mjs` 出 a_bogus（约 1.4 s）→ 一个 GET → `play_addr.url_list[0]`
- 风控：一次深审只发 1 个详情请求，不模拟播放/点击
- ⚠️ 留影默认的 `scene`（镜头切换）抽帧对静态短视频**一帧都选不中**（ffmpeg 报 -22），
  所以 kit 调它时固定传 `mode: 'even'`（按时长均匀取）

## 三、配置（config.json 新增）

```json
{
  "conch": {
    "enabled": true,
    "url": "http://127.0.0.1:7801",
    "token": "",
    "homeDir": "<海螺目录>",
    "personaFallback": "",
    "personaMaxChars": 4200,
    "toneSamples": 3,
    "memoryTopics": ["刷视频", "抖音", "B站", "爸", "口味", "喜欢"]
  },
  "ring": {
    "mcpServer": "",
    "dbPath": ""
  },
  "media": {
    "mode": "fast",
    "deepPerRound": { "bili": 2, "douyin": 1 },
    "frames": 3,
    "audio": "auto",
    "liuyingHome": "<留影目录>"
  }
}
```

- `conch.enabled=false`：整条桥关掉，行为回到改之前
- `personaMaxChars`：人设注入上限（按小节抽，不是硬截断）
- `media.audio`：`auto` = 没字幕才听；`always` = 都听；`off` = 不听
- `media.mode`：`fast` 只看文字；`deep` 才抽帧/听声

## 四、降级链（任何一环挂了都不许拖垮值班轮）

| 挂的环节 | 降级 |
|---|---|
| 海螺 7801 连不上 | 用 `state/conch-bridge-cache.json` 里上次的人设 → 再退 `~/.dsh/douyin-duty/persona.md` → 再退空（日志写明） |
| 环形的心起不来 | 只丢记忆块，其余照常 |
| 留影目录不存在 | 深模式自动退回快模式，`kit.log` 记一行 |
| 视觉/ASR 失败 | 如实写「没看到画面 / 没听到声音」，**绝不编**（沿用章程的老规矩） |
| 视频超过 20 MB | 跳过深审，退快模式 |

# 九、后续修正（2026-11-09）

第一版有三处做得不对，按使用者的意见改掉了。记在这里，免得以后又被"看起来对"的做法带回去。

## 9.1 她不是被扮演的——写不写由她定

**第一版错在哪**：我把她以前说过的原话当"语气样本"塞进 prompt，又写"写日报时用她自己的话：像在 QQ 里跟爸说话、短句、有语气词"。

那等于给了她一份**自己的模仿指南**。她照着说，说出来的就是"像她的东西"，不是她。使用者的原话是：

> 日报不是用她的口吻，是让她选择写不写，写的话自己写。

**现在**：

| | 第一版 | 现在 |
|---|---|---|
| 语气样本 | 注入 3 条原话 | `toneSamples: 0`（默认不注入） |
| 指令 | 「像她那样说话，短句、有语气词」 | 「这些视频**你自己在看**。写不写、写几条、写多长，你自己定」 |
| 配额 | 「本轮最多挑 N 条」 | 「最多记 N 条——**也可以一条都不记**」 |
| 没写 | 校验报错 | `（这轮没写）` 是她的合法决定，返回 `skipped`，不落盘、不报警 |

留下的只有格式（`### <ID>` + 档位行），因为程序要靠它计数——**这是程序的约束，不是对她的要求**。

## 9.2 声音：a 和 b 是组合，不是二选一

**第一版错在哪**：我把它写成了"a 换 b"（字幕换 ASR），使用者指出应该是"a 兜不住才用 b"。

**现在**：

```
有字幕 → 直接读（免费、秒出）
  ↓ 没有
yt-dlp -f bestaudio 只拉音轨（不下整条视频）→ 留影 SenseVoice 转文字
  ↓ 还是不行
如实写「没听到」
```

画面不动：继续用 `bili_frames` 故事板帧，**不为听声音去下整条视频**。

实测：yt-dlp 下 5.4MB m4a 用 5.5s；留影 ASR 转 4s 出文字。

## 9.3 key 要先验后存

原来要先点「保存」再点「测试连通」——存进去的可能是坏 key。

现在 `brainTest(cfg, override)` 接受页面上**还没保存**的 key/baseUrl/model，`/api/brain/test` 接 body，前端把输入框的值直接送去验：

- 401 → 「key 不对，或已经失效」
- 403 + quota → 「这个 key 的额度用完了：充值或换一个」
- 404 → 「baseURL 或模型名不对」
- 429 → 「限流了」
- 连不上 → 带 `ENOTFOUND` / `ECONNREFUSED` 这类具体 code
- 通了 → `✓ <模型名> 连通（xxx ms）：就绪 —— 别忘了点保存`
