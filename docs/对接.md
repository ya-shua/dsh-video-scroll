# Snow Video Kit（娱乐）对接说明

机器可读的部分在插件包根 `metadata.json`（`capabilities` / `standalone` / `contract`）；本文档讲人怎么接。

## 定位

海螺「娱乐」app：B站/抖音**值班刷视频** —— 工作台（默认 `127.0.0.1:8412`）+ 6 个 MCP 工具 + 可选的值班计划。

包分两层，别搬错：

- `刷视频插件/` —— 插件包根，`metadata.json` 在这里，还有 `docs/`、`dsh-video-scroll/`
- `snow-video-kit/` —— 运行目录（`src/` 代码、`config.json`、`state/` 私有状态），`metadata.json` 的 `launch.cwd`

## 三种接法

1. **工作台 HTTP**
   `cd snow-video-kit && node src/index.js` → `http://127.0.0.1:8412/`。
   页面之外还有 `/api/status`、`/api/logs`、`/api/brain`、`/api/memory`、`/api/run`、`/api/update/*` 等；端口读 `config.json:web.port`。

2. **MCP（工具调用）**
   - stdio：`node src/kit-mcp.mjs`（零依赖，DSH / 任意 MCP 客户端都能挂）
   - HTTP 无状态：`POST /mcp`，令牌 = `state/console-token`（`?token=` 或 `x-console-token` 头）

   工具 6 个：`video_status`、`video_latest_report`、`video_run_round`、`video_bili_hot`、`video_bili_search`、`video_memory`。

3. **值班计划 / 手动派轮**
   `config.schedule.enabled` + 在窗口内 + QQ 在线 + 大脑已配置 → 每 10 分钟检查一次自动派轮；
   也可 `POST /api/run`（`{"kind":"bili"|"douyin"}`）立刻派一轮。

## 能力清单

`GET /api/manifest` → `metadata.capabilities`（6 条），各自对应的入口：

| 能力 | 入口 |
|---|---|
| B站/抖音值班刷视频 | `POST /api/run`、`video_run_round`、`config.schedule` |
| 候选挑片与打分 | `/api/status`（rounds / qq / brain）、`video_status` |
| 写值班日报 | `GET /api/report?kind=`、`video_latest_report` |
| 6 个 MCP 工具（video_*） | `POST /mcp`、`node src/kit-mcp.mjs`、`GET /api/tools` |
| 跨平台视频记忆库 | `/api/memory`、`video_memory` |
| 本机工作台面板 | `GET /`、`/panel.html` |

**「能不能用上全部功能」**：评论/私信这类完整交互走 `/api/bili-duty/*`、`/api/douyin-duty/*`，代理到 `127.0.0.1:8390`
（`dsh-video-scroll` 平台后台）。不接那个后台，就只有「挑片 + 报告 + 记忆」这套值班能力。

## 契约端点（只读）

### `GET /api/health`

```json
{"ok":true,"id":"video","version":"0.7.1","uptime_s":4}
```

- `id` 取自插件根 `metadata.json` 的 `id`
- `version` 取 `src/version.mjs` 的 `KIT_VERSION`（读 `package.json:version`）
- `uptime_s` 从进程启动算到本次请求

### `GET /api/manifest`

```json
{
  "ok": true,
  "metadata": { "id": "video", "version": "0.7.1", "capabilities": ["…"], "standalone": {"…": "…"}, "contract": "docs/对接.md", "…": "…" },
  "runtime": { "port": 8413, "pid": 38236, "started_at": "2026-11-09T23:30:12+08:00" }
}
```

- `metadata` 是 `metadata.json` 原文：先找 `snow-video-kit/metadata.json`，没有就找上一层（插件包布局）
- `runtime.port` 是**实际监听端口**（被 `startWeb({port})` 或 `config.json:web.port` 改过时与 `metadata.port` 不同）
- `started_at` 是带本地时区偏移的 ISO 8601

两个端点都不带 key、令牌、用户名、绝对路径、视频清单内容。

**版本唯一来源**：`package.json:version`。`src/version.mjs` 的 `KIT_VERSION`、`/api/health`、MCP `serverInfo.version` 三处都读它；
`metadata.json:version` 是副本，必须与之一致。

## 失败语义

| 情况 | 表现 | 宿主该怎么办 |
|---|---|---|
| 端口被占 | `server.on('error')` **只写日志、进程不退** → 看着像活着，请求却打不进 | 唯一判据是 `/api/health` 通不通；不通就换端口或停旧实例 |
| `metadata.json` 找不到/坏 | `metadata` 返回 `{}`，`ok` 仍 `true` | 「活着」与「元数据坏了」分开判断 |
| `/mcp` 令牌不对 | 403 + 中文错误 | 读 `state/console-token` |
| `/mcp` 未知方法 | JSON-RPC `-32601`（HTTP 200） | — |
| 工具内部抛错 | HTTP 200 + `isError: true`（MCP 约定） | 看 `content[0].text` |
| 平台后台 8390 没起 | `/api/bili-duty/*` 返回 503 | 只影响评论/私信，值班轮不受影响 |
| 公网暴露 | 工作台无登录（只听 127.0.0.1） | 别把端口转出去 |

## 单独运行

只要 Node ≥ 22，**零 npm 依赖**：

```bash
cd snow-video-kit
node src/index.js          # 工作台 + 探活 + /api/manifest
node src/check.js          # 环境自检（配置 / SnowLuma / 大脑 / 桥接 / 记忆）
```

- `state/` 首次启动自动生成 `console-token` 与日志；`config.json` 不存在时用默认值落盘。
- 真刷片还需要：B站/抖音 MCP 子进程（Python/Node 侧依赖）、大脑 API key；值班轮额外要求 QQ（SnowLuma）在线。
- `startWeb({ port })` 支持换端口（自检用），默认仍读 `config.json:web.port`。

## 自检 curl

```bash
curl -s http://127.0.0.1:8412/api/health
curl -s http://127.0.0.1:8412/api/manifest
```

合格的标志：两条都是合法 JSON 且 `"ok": true`；`health.version` 与 `package.json` 的 `version` 一致；
`manifest.runtime.port` 等于实际监听端口。
