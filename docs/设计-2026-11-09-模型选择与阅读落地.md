## 一、大脑：获取可用模型

### 1. 要解决的问题

原来模型名是一个纯文本输入框（`#brain-model`），用户得自己知道并准确敲出模型名，
拼错就 404，也不知道这个 key 到底能用哪些模型。OpenAI 兼容网关一般提供
`GET /models`，直接拉清单最省事。

### 2. 后端

`brain.mjs` 新增 `listModels(cfg, override)`：

- 请求 `baseUrl + /models`，带 `Authorization: Bearer <key>`。
- override 里的 baseUrl/key 优先，页面上还没保存也能先拉（与 brainTest 同一思路）。
- 兼容不同网关返回：字段可能是 `data` 或 `models`；每项可能是字符串或 `{id}` 对象。
- 提取 id、去重、按字母排序后返回 `{ ok:true, models:[...] }`。
- 网络失败、非 200、空列表都返回 `{ ok:false, error }`，error 用中文说清原因。

`server.mjs` 新增路由：

- `POST /api/brain/models`：body 接 `{baseUrl, key}`，调 listModels，返回结果。

### 3. 前端

- 模型输入框保留，加 `list="brain-model-list"`，关联一个 `datalist#brain-model-list`。
- 旁边加按钮「🔄 获取模型」`#brain-fetch-models`。
- 点击 → 调 `/api/brain/models`（带当前页面的 baseUrl 和 key）：
  - 成功：把模型填进 datalist（每个一个 `<option value=...>`），提示数量，
    用户点输入框即可下拉选，也仍能手动填。
  - 失败：结果区显示后端返回的中文 error。

### 4. 为什么用 datalist 而不是 select

- datalist 既能从拉到的清单里选，又保留手填能力，接口不支持 /models 时不会卡死。
- 改动小，原 `#brain-model` 的 id、保存和测试逻辑都不用动。

## 二、阅读功能落地（看小说 / 看贴吧）

### 1. 现状

11-07 已完成底层：`reader-chrome.mjs`（专用浏览器底座：独立 profile、端口段 9434–9473、
visibleLogin 可见窗口登录）和 `reads.mjs`（采集 / 阅读 / runReads 工具循环），
config.js 也有 `reads` 默认段（默认全关）。但当时缺：后端路由、工作台页面、独立进程派发，
runReads 没有任何入口能被触发。本次把这三块补齐。

### 2. reads.mjs 新增

- `readsState(kind)`：读 `state/reads-<kind>.json`，running 超过 2 小时视为 stale。
- `readsRunning(kind)`：是否正在跑。
- `kickReadsDetached(kind, reason)`：写 queued 状态，spawn 独立进程 `reads-runner.mjs`，
  立即返回（调用方退出也不影响），与值班轮的 kickRoundDetached 同一模式。
- `startReaderLogin(kind)`：调 reader-chrome 的 visibleLogin，
  贴吧开 tieba.baidu.com、小说开 fanqienovel.com，cookies 存 reader-profile，登录一次即可。

### 3. 新建 reads-runner.mjs

独立进程入口 `node reads-runner.mjs --kind novel|tieba [--reason ...]`：

- 写 running 状态 → 调 runReads → 按结果写 done/skipped/error。
- 退出码 0 = 成功/跳过，1 = 失败。

### 4. server.mjs 新增路由

| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/reads` | GET | 返回 reads 配置 + 贴吧/小说两个状态 |
| `/api/reads` | POST | 保存开关、关注吧、每轮条数、追更书单（后端裁剪、过滤空值） |
| `/api/reads/run` | POST | body `{kind}`，kickReadsDetached 异步派发 |
| `/api/reads/login` | POST | body `{kind}`，开可见窗口登录 |

### 5. 前端页面

导航「平台」组新增「📖 阅读」，对应 `#view-reading`：

- 顶部操作条：看贴吧一轮 / 看小说一轮 / 刷新，右侧两个状态徽章。
- 看贴吧卡：启用开关、每轮最多推几帖、关注的吧（逗号分隔）、贴吧登录按钮。
- 看小说卡：启用开关、追更书单（每行书名 + 目录页链接，可动态加/删）、
  加一本书、番茄登录、统一保存条。
- 视觉沿用 setgroup / formgrid / 深色风格，和 B站、抖音页一致。

### 6. 完整链路

设置里开开关、填吧名/书单并保存 → 点「一轮」→ 后端独立进程跑 runReads：
真浏览器打开候选 → 她调 read_tieba_thread / read_chapter 亲自读 → 输出 Markdown
落盘 `data/reads/<日期>-<kind>.md` + 记忆库入库（platform=tieba/novel）→ 状态转 done。
