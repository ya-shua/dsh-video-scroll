# 设计：界面收敛、去标识与功能精简（2026-11-09）

> 一句话：使用方式定型为「海螺桥接 → 智能体经 MCP 自己刷视频，人只看状态/结果」之后，
> 把工作台改成配合这个方式的样子——人不需要的操作删掉、平台设置全部舒展、
> 原作者标识抹干净、连不上网时的报错不再吓人。

---

## 一、为什么改

主线使用方式已经明确，跟早期「人在面板上手动点」完全不同：

```
海螺（她的人设/记忆）
   └─ 桥接调用 snow-video-kit（8412）
        └─ 智能体经 MCP 自主刷 B站 / 抖音
             └─ 人 mostly 只看状态和结果，不亲手操作
```

由此推出四条界面要求：

1. 人不会去点的手动操作、看不懂的页面，删掉或搬走
2. 两个平台的设置不要折叠，全部舒展到各自页面
3. 界面上不能留原插件 / 原宿主的标识（DSH、SnowLuma、原版本号）
4. 环境类报错（网络、凭证）要讲人话、分轻重，不能一律红色吓人

## 五、删除「它刷过的视频」

核查结论：**只有 B站有这个功能，抖音本来就没有**，所以只动 B站。

一次删干净，不留死代码：

- HTML：整个「它刷过的视频」卡片（含 `nb-wtotal` / `nb-chips` / `nb-wq` / `nb-wsort` / `nb-watched`）。
- JS 函数：`nbChips`、`loadNbWatched` 两个整函数删除。
- JS 变量：`nbWState`、`nbWTier`、`nbWOff` 删除；`nbCfg` 仍被 `loadBili` 使用，**保留**。
- 事件绑定：`nb-wq` 回车查询、`nb-wsort` 切换排序两个绑定删除。
- `loadBili` 内的调用与 catch 里对 `nb-watched` 的兜底赋值一并清掉（catch 里保留 `nb-badges` 兜底和 toast）。

删完 B站页只剩：顶部状态卡（跑一轮 / 刷新 / 徽章）+ 设置卡。收藏夹相关的 `loadNbFavFolders` 不受影响。

## 六、更新检查：网络失败要友好

左下角「一键更新」靠 `git fetch` 对比 origin/main。本机访问 GitHub 经常被重置，
旧逻辑把 git 的原始报错（`fatal: unable to access ... Connection was reset`）直接甩到界面、亮红点。

改法：

1. `updater.mjs` 用正则识别网络连接类错误（unable to access / connection reset / recv failure /
   could not resolve / timed out / connection refused 等）。
2. 命中网络错误时返回 `{ ok:false, network:true, note:'暂时连不上更新服务器（网络问题），不影响使用' }`，
   不把原始 git 英文报错暴露出来。
3. 前端 `updateCheck` 遇到 `network`：状态点用**中性灰**（不用红色 bad）、不弹错误 toast；
   网络恢复后正常显示绿点「已是最新」或黄点「有新版本」。

## 十、回滚

- 代码：`git restore <文件>` 或 `git revert <commit>`，改动均在工作区、未提交时可整体丢弃。
- 配置：`config.json` 未被本次改动破坏；`conch.enabled=false` 可单独关掉桥接。
- 后端回滚后重启一次服务即可；前端回滚后刷新页面即可。
